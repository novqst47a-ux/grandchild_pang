# 프로토타입 제작 프롬프트

새 세션에 아래 블록을 그대로 붙여넣어 사용한다.

목적은 게임 전체가 아니라 **사진 처리 파이프라인이 모바일 브라우저에서 실제로 동작하는지**
검증하는 것이다. 설계 배경은 [webapp-migration-plan.md](./webapp-migration-plan.md) 참고.

---

```
매치3 퍼즐 게임용 "사진 블록 생성기" 프로토타입을 단일 HTML 파일로 만들어주세요.
게임 로직은 제외하고, 사진 처리 파이프라인만 검증하는 것이 목적입니다.

## 목적
사용자가 프레임(예: 토끼 얼굴)을 고르고 자기 사진을 넣어
매치3 블록 텍스처를 만드는 흐름이 모바일 브라우저에서
실제로 동작하는지 확인.

## 필요 기능
1. 프레임 선택
   - 가운데가 뚫린 프레임 3~4종. 외부 이미지 없이 코드로 그려주세요
     (SVG 또는 canvas). 색/실루엣이 뚜렷하게 구분되도록.

2. 사진 입력
   - <input type="file" accept="image/*" capture="environment">
   - createImageBitmap(file, { imageOrientation: 'from-image' })로 EXIF 회전 보정

3. 크롭 UI
   - 프레임 구멍 모양을 오버레이로 보여주고 그 안에서 사진을 팬/줌
   - Pointer Events 사용 (모바일 한 손가락 드래그 + 핀치 줌)

4. 합성
   - 오프스크린 canvas에서 마스크 합성 (globalCompositeOperation)
   - 결과: 256x256 WebP blob

5. 저장
   - IndexedDB에 저장 (idb 라이브러리 또는 순수 IndexedDB)
   - navigator.storage.persist() 호출
   - 저장된 블록 목록을 그리드로 표시
   - "전체 초기화" 버튼

6. 블록 제거 연출
   - 블록을 탭하면 사라지는 애니메이션
   - !! 중요: 사진(얼굴)을 조각내거나 부수는 연출은 절대 사용하지 마세요.
     고령자가 손주나 가족 사진을 쓰는 경우가 많아 심리적으로 불쾌합니다.
   - 대신 이런 방향으로:
     * 블록이 살짝 커졌다가 부드럽게 축소되며 페이드아웃
       (사진은 마지막까지 온전한 형태 유지)
     * 사라진 자리에 프레임 색상 기반의 반짝임/별 파티클이 퍼짐
     * 위로 살짝 떠오르며 사라지는 느낌도 좋음
   - 즉 "부서진다"가 아니라 "칭찬받고 사라진다"는 인상이 목표

## 제약
- 단일 HTML 파일, 외부 CDN 최소화, 서버/업로드 없음
- 안드로이드 크롬 기준, 세로 화면 우선
- 프레임워크 없이 vanilla JS + canvas

## 확인하고 싶은 것
- 안드로이드에서 카메라/갤러리가 제대로 열리는지
- 세로 사진이 눕지 않는지
- 완성된 블록 6종을 나란히 놓았을 때 서로 구분이 되는지
  (구분이 어려우면 프레임 비중을 키우는 방향으로 조정)
```

## 검증 체크리스트

프로토타입을 실제 안드로이드 폰에서 열어 확인할 것.

- [ ] 카메라/갤러리 선택 시트가 정상적으로 뜨는가
- [ ] 세로로 찍은 사진이 눕지 않는가 (EXIF)
- [ ] 핀치 줌이 버벅이지 않는가
- [ ] 브라우저를 완전히 종료 후 재접속해도 블록이 남아 있는가
- [ ] **블록 6종을 나란히 놓았을 때 한눈에 구분되는가** ← 가장 중요
- [ ] 블록이 사라지는 연출이 가족 사진에 써도 거부감 없는가

마지막 항목이 실패하면 게임 디자인 자체를 조정해야 한다.
프레임 비중을 키우고 사진 영역을 줄이는 방향으로 대응.
